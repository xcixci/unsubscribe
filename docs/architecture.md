# Architecture

## Principles

- **Static and private.** One HTML page, one JS bundle, one catalogue JSON. No server, no cookies, no analytics, no third-party requests at runtime.
- **The user's number wins.** Catalogue prices are references; every total uses what the user says they pay.
- **Honest by construction.** A "saving" is only shown when the alternative's annual cost is lower than what the user pays. Feature-reducing options are labelled. Bundles are never called savings. Unverified data is labelled everywhere it appears.
- **Logic outside React.** `src/domain/` is plain TypeScript with unit tests. UI components only format and arrange.

## Layers

```
pages/ + components/        React UI
        │
state/                      Providers: CatalogueProvider, SubscriptionsProvider, ToastProvider
        │
domain/                     billing · dates · money · spending · recommendations · offers · ics · catalogueQueries
        │
storage/ (personal)         SubscriptionRepository ← LocalStorageRepository
data/    (public)           loadCatalogue() → /data/catalogue.json
```

## Money maths (`src/domain/billing.ts`)

Everything is converted through "cycles per year":

| Cycle | Cycles per year | Monthly equivalent |
|---|---|---|
| Monthly | 12 | price |
| Quarterly | 4 | price ÷ 3 |
| Half-yearly | 2 | price ÷ 6 |
| Annual | 1 | price ÷ 12 |
| Every N months | 12 ÷ N | price ÷ N |
| Every N days | 365 ÷ N | price × 365 ÷ N ÷ 12 |

Annual = price × cycles per year. Five-year = annual × 5 (no price changes assumed, labelled as an estimate). Values stay unrounded until display. A 28-day pack correctly bills about 13.04 times a year, not 12.

## Personal data

Stored under the localStorage key `unsubscribe:v1:personal-data`:

```ts
{ app: 'unsubscribe', schemaVersion: 1, updatedAt, subscriptions: UserSubscription[] }
```

`UserSubscription` (see `src/domain/types.ts`): `id, serviceId | custom{name, category, websiteUrl}, planId, amount, currency, billing, nextRenewal, paymentMethod, paymentLabel, notes, status, reminderOffsets, createdAt, updatedAt`.

The same shape is the export/import file. `storage/validate.ts` checks every field on load and import, drops unknown fields, rejects bad amounts/cycles/duplicate IDs, and strips notes that look like card or account numbers. Unreadable stored data is kept under a separate key instead of being deleted.

### Adding cloud sync later

`SubscriptionRepository` (`src/storage/repository.ts`) is the only thing the app uses to persist personal data:

```ts
interface SubscriptionRepository {
  readonly location: string;
  load(): Promise<PersonalData>;
  save(data: PersonalData): Promise<void>;
  clear(): Promise<void>;
}
```

A future `ApiRepository` (Supabase, Firebase, a custom API) implements the same interface and is passed to `<SubscriptionsProvider repository={…}>`. A first-sign-in migration can call `LocalStorageRepository.load()` and upload the result. `schemaVersion` exists so the format can evolve with migrations.

## Catalogue

Generated by `scripts/build-catalogue.mjs` from CSVs (see [catalogue.md](catalogue.md)). Only whitelisted columns are published. Types: `Service`, `Plan`, `Offer`, `Bundle` in `src/domain/types.ts`. `plan_group` links the same product across billing cycles; `plan_type` marks student/family/duo plans.

## Recommendations (`src/domain/recommendations.ts`)

For each subscription, ranked by value to the user:

1. Same plan on a different billing cycle that costs less (no feature loss; may be paid upfront)
2. Verified offers for the service
3. Student plans (eligibility needed)
4. Cheaper tiers, flagged "Fewer features" with the features shown
5. Unverified offers
6. Shared (family/duo) plans, with the break-even number of people; never a claimed saving
7. Bundles that include the service; never a claimed saving
8. A price check when the user pays more, or less, than today's listed price (warns about losing legacy prices)

## Reminders (`src/domain/ics.ts`)

RFC 5545 calendar files. Each reminder is its own all-day event (so it shows in Google Calendar, which ignores alarms in imported files), repeating with the billing cycle (`RRULE`), with a 9 am alarm for apps that honour `VALARM`. Lines are folded at 75 octets without splitting UTF-8 characters.

## Future capabilities and where they go

| Capability | Where it plugs in |
|---|---|
| Accounts and sync | New `SubscriptionRepository`; auth provider around `SubscriptionsProvider`. |
| Statement upload / recurring-payment detection | A new `domain/detection` module producing `NewSubscription[]` for review, then `add()`. Keep parsing on-device where possible. |
| UPI AutoPay guidance, cancellation help | Per-service fields in SERVICES (e.g. `cancel_url`, `autopay_notes`) and a section on the service page. |
| Renewal notifications | Needs a backend or Web Push; the `.ics` route stays as the no-account option. |
| AI-assisted analysis | Reads the same `SpendSummary` and `Recommendation[]`; must keep the "honest saving" rules. |
